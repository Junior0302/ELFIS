# 17 — Creative Direction B — Connected Ecosystem

**Phase :** B0.4 — Creative Exploration  
**Code :** `DIR-B`  
**Inspirations (tonalité, pas copie) :** Microsoft 365 · Google Workspace · Adobe  
**Statut :** exploration — **aucun logo final choisi**, aucun SVG/PNG.

Conforme à B0.1 / B0.2 / B0.3 : Pilot Mark = symbole de **connexion des métiers** ; Master Brand / Product Brands ; lockups ; checklist.

---

## 1 — Philosophie

ELFIS comme **écosystème d’expertises reliées**.  
Chaque Pilot est une application claire ; le Mark et la plateforme racontent le lien.

Narratif : *« Une plateforme. Plusieurs expertises. Une connexion. »*  
(aligné promesse Brand Book)

---

## 2 — Personnalité

| Trait | Intensité |
|-------|-----------|
| Connecté / systémique | Très fort |
| Clair / professionnel | Fort |
| Minimal puriste | Moyen |
| Institutionnel | Moyen-fort |
| Expressif | Moyen (contrôlé) |

Voix : plateforme d’abord, puis spécialité métier.

---

## 3 — Émotion

Appartenance · continuité · maîtrise multi-métiers · confiance « suite ».

---

## 4 — Type de clients

- PME / ETI multi-équipes (finance + commercial + docs)  
- Organisations qui veulent **une suite** plutôt qu’un outil isolé  
- Décideurs sensibles à la vision plateforme  

Convient aussi aux grands comptes **si** le ton reste sobre (pas gadget).

---

## 5 — Palette (application — HEX Brand Book)

| Usage | Règle DIR-B |
|-------|-------------|
| Master | Navy dominant sur surfaces publiques |
| Product | Primary Pilot visible dans shell (sidebar, actifs) |
| Accents | Un accent produit + accent plateforme sur surfaces partagées |
| Launcher | Pastilles primary par Pilot — lecture « famille d’apps » |

Secondary utilisées comme **fonds d’écosystème** (plus présentes qu’en DIR-A, sans saturations agressives).

---

## 6 — Composition

- Mark souvent en **ancre visuelle** (landing, splash, launcher)  
- Zones « famille de produits » : grille d’apps cohérente  
- Séparation claire Platform Shell / Product Shell ([07](./07-platform-vs-product.md))  
- Connexion visuelle : alignements, filets légers, pas de réseau illustré kitsch  

---

## 7 — Hiérarchie

1. **Pilot Mark** (connexion)  
2. Nom de marque (ELFIS Core ou Pilot)  
3. Signature `by ELFIS Core` sur produits  
4. Contenu métier  

Le Mark n’est pas un détail favicon : il porte le récit.

---

## 8 — Animation

- Motif phare : **connexion** (apparition progressive d’éléments liés) — sans morphing du glyphe  
- Transition produit : Mark stable, wordmark + primary changent ([06](./06-design-dna.md))  
- Launcher : stagger léger des pastilles  
- Reduced motion : état final immédiat  

---

## 9 — Surfaces

### Landing

Hero : Mark + `ELFIS Core` + une phrase plateforme.  
Ensuite : section « Les Pilot » — même Mark teinté + wordmarks (pas 10 symboles).  
CTA vers login / démo.

### Login

Mark + `ELFIS Core` ; fond navy ou secondary plateforme.  
Message implicite : on entre dans **la suite**, pas dans une app isolée.

### Launcher

Surface vitrine de DIR-B : grille Pilot, Mark teinté, noms CamelCase, signature visuelle famille.  
App Launcher = composant **plateforme**.

### Sidebar

Lockup `product-signed-h` recommandé.  
Actif = primary produit ; header reste lié à ELFIS via `by`.

### Topbar

Mark + nom produit ; switcher / launcher accessible ; identité produit lisible en 1 regard.

---

## 10 — Illustrations

- Diagrammes de lien, flux sobres, « nœuds » abstraits **hors** du Mark  
- Grammaire commune ; couleurs = primary des Pilot concernés  
- Interdit : collages clipart multi-marques  

---

## 11 — Icônes

Stroke DNA commun.  
États actifs teintés primary.  
Launcher icons = Mark ou icône métier **UI** (pas un second logo).

---

## 12 — Motion

Connexion · transition de marque · apparition de famille d’apps.  
Pas d’oscillation de thème.

---

## 13 — Applications mobiles

- Splash : `mark-name-v` ou `product-signed-v`  
- Bottom nav métier ; accès launcher plateforme  
- Même Mark teinté que desktop  

---

## 14 — PDF

- En-tête Mark + nom ; pied de page `by ELFIS Core` pour docs Pilot  
- Watermark Mark optionnel faible opacité  
- Couverture peut montrer la famille (liste, pas mosaïque chaotique)  

---

## 15 — Emails

- Header écosystème : Mark + ELFIS Core ou Pilot signé  
- Modules « Autres Pilot » sobres en footer marketing  
- Primary selon expéditeur (Core vs Pilot)  

---

## 17 — Conformité Brand Book

| Contrainte | Respect |
|------------|---------|
| Narratif Mark = connexion | **Maximal** (cœur de DIR-B) |
| Un glyphe pour N Pilot | Oui — démontré via launcher / landing |
| Pas de picto métier dans le Mark | Oui |
| Extensibilité AIPilot, etc. | Naturelle (nouvelle pastille) |

---

## 18 — Forces / vigilances (B seule)

**Forces :** aligne la promesse plateforme · Mark valorisé · scalabilité famille · différenciation vs outil mono-métier.  
**Vigilances :** densifier trop le launcher/landing ; glisser vers « suite Microsoft clone » ; secondary trop présentes.
