## Détail par critère

### Avantages

- **A :** vitesse de compréhension UI · excellence micro-interactions · peu de dette visuelle.  
- **B :** aligne `Pilot Mark = connexion` · Master/Product évident · onboarding mental « suite ».  
- **C :** crédibilité achats/DSI · PDF/emails naturels · densité workspace acceptée.

### Inconvénients

- **A :** raconte mal « plusieurs expertises » ; Mark peut paraître favicon.  
- **B :** tentation de surcharger la landing ; secondary trop présentes.  
- **C :** peut contredire le DNA « pas stickers / pas glow » si mal exécuté ; moins unique.

### Scalabilité

Ajouter SupportPilot / AIPilot :  
- A = nouvelle teinte, peu de storytelling.  
- B = nouvelle pastille dans la grille famille.  
- C = nouveau module brochure.

### Lisibilité

A et B gagnent sur le premier viewport.  
C gagne sur les pages « preuve » longues, perd en hero épuré.

### Premium

Trois premiums **non fongibles** : craft (A), système (B), institution (C).  
ELFIS doit en choisir un comme **dominant**, pas les trois à parts égales.

### Reconnaissance

B maximise la mémorisation du **Mark partagé**.  
A et C mémorisent surtout le wordmark / le discours.

### Différenciation

B se distingue le mieux du « simple outil compta recoloré ».  
A et C se rapprochent de référents très peuplés.

### Évolutivité

B est la seule direction où l’**architecture logo B0.3** (héritage Mark → lockups → checklist) est **scénarisée** partout (launcher, landing, splash, emails).

## Compatibilité contraintes dures (rappel)

| Contrainte Brand Book | A | B | C |
|-----------------------|---|---|---|
| Un seul Mark / une grille | OK | OK | OK |
| Palette figée | OK | OK | OK |
| Platform ≠ Product | OK | OK (renforcé) | OK |
| Pas de morphing Mark | OK | OK | OK |
| Signature `by ELFIS Core` | OK | OK (central) | OK |

Aucune direction n’est **disqualifiée** ; elles diffèrent par l’**expression**.
